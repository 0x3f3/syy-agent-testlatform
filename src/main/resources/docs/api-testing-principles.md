# API 自动化测试设计原则

## 测试分层
- 正常路径：验证有效输入、成功状态码、响应结构和关键业务字段。
- 参数校验：验证必填字段缺失、类型错误、格式错误、长度边界和枚举值。
- 边界测试：验证最小值、最大值、空集合、分页边界、数值上下限。
- 权限测试：验证缺少令牌、令牌无效、角色权限不足和资源越权。
- 业务异常：验证资源不存在、重复创建、状态冲突、库存不足等业务规则。

## 断言策略
- 首先校验 HTTP 状态码。
- 对 JSON 响应校验关键字段存在性、字段类型和业务值。
- 对分页响应校验 page、pageSize、total、items。
- 对错误响应校验错误码和可读错误信息，不要只依赖 HTTP 200。
- 断言必须来自 OpenAPI 契约、示例或明确业务规则；不确定时使用结构性断言，不要编造字段。

## 测试数据安全
- 不在测试用例、日志和报告中保存真实密码、访问令牌、API Key 或 Cookie。
- 使用环境变量或测试数据占位符提供凭据。
- 报告与执行记录展示时对 password、token、secret、authorization、cookie 等字段脱敏。

## 接口依赖
- 登录接口通常先于受保护接口执行。
- 创建资源后可查询、更新和删除该资源。
- 有状态副作用的测试应使用独立测试数据，避免用例顺序依赖。
